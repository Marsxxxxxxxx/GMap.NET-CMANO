# 清晰度与叠加精度改进计划

本次先完成 2.1.7 升级基线。以下是基于 2018 年程序实际导出逻辑的下一阶段建议，不是已实现功能。

## 1. 显式保留原始细节

- 增加“保留原始分辨率”选项，避免默认因 10 MB 上限而缩图。
- 以目标像素尺寸、覆盖范围和地面分辨率管理导出质量，并显示预计内存用量。
- 必须缩小时，从原始图像一次重采样到最终尺寸，避免多次 80% 缩放。
- 大区域优先分块输出，为每块生成独立 PGW，控制游戏加载压力。

## 2. 根据实际输出重算地理定位

- 用最终图像的实际宽、高计算 PGW 的每像素坐标增量，替换 `1.25^n` 的估算。
- 区分选择框的地理边界和取整后的瓦片像素边界，保证拼接图像与坐标范围一致。
- 按 Worldfile 规范处理左上像素中心；同时核对目标游戏版本的实际读取约定，避免只改半像素后引入兼容性偏差。
- 写文件时明确使用 `InvariantCulture`，并验证缩图、负经纬度和不同 Windows 区域设置。

## 3. 明确图源投影并重投影

- 明确源影像坐标系。对 Web Mercator 瓦片，先拼接并保留正确的源坐标，再重投影到游戏导入流程所需的经纬度网格。
- 不能仅给 Mercator 图像写经纬度 PGW 来代替重投影；这种线性近似会在大范围和高纬度更明显。
- 首先用 GDAL 建立独立对照样本，再决定内置 GDAL 还是实现受控范围内的采样转换。
- 对跨越 180° 经线的区域明确拆分；不把所有图源都假定为同一坐标基准。

## 4. 验证与可诊断导出

- 用同一机场或港口的中心、四角及若干地物作为对照点，比较原版、升级基线与改进版。
- 分开记录软件配准误差、底图自身误差和影像拍摄时间差，不承诺高于源数据的真实精度。
- 记录每张导出的图源、缩放级别、像素尺寸、地理边界和处理步骤。
- 缺瓦片时显示缺口并明确提示；不把下载失败的拼图当作完整输出。
